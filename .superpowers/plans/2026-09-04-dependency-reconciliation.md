# Dependency Reconciliation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Bring `.pre-commit-config.yaml`, `.serena/project.yml`, and `uv.lock` to current versions, absorbing the Ruff 0.16 rule-surface change without altering runtime behaviour.

**Architecture:** This repository pins tool versions on two independent axes that CI runs separately — `rev:` pins in `.pre-commit-config.yaml`, and resolutions in `uv.lock` that drive the three `local` `language: system` hooks. They are currently skewed (Ruff `0.15.15` vs `0.15.18`). The plan moves both axes to the same Ruff version, absorbs the four new rules that `select = ["ALL"]` exposes, then bumps the two remaining unmeasured tools in isolated, individually-droppable commits.

**Tech Stack:** uv, pre-commit, Ruff 0.16.6, ty, zensical, pytest, repo-release-tools (rrt)

**Spec:** `.superpowers/specs/2026-09-04-dependency-reconciliation-design.md`

## Global Constraints

- Package manager is **uv exclusively**. Never `pip`. Run tools via `uv run` or `uvx`.
- Python 3.12+. Ruff `target-version = "py312"`; ty targets `3.12`.
- Test coverage floor is **95%** over `src/mcp_zen_of_languages/` — `pytest` fails below it.
- Docstring coverage floor is **90%** on `src/` (interrogate).
- `ty check` runs with `--error-on-warning` in CI. A warning is a failure.
- Commit subjects must satisfy **Conventional Commits**; `rrt-commit-subject` enforces this.
- Branch names are enforced by `rrt-branch-name`. Work stays on `claude/dependency-update-plan-e7326c`.
- Never `git commit --no-verify`. If a hook auto-fixes files, stage the fixes and re-commit.
- Never edit `[project] version` or `__version__` by hand; that is `rrt bump`'s job. This plan touches neither.

## Two traps found while preparing this plan

**Trap 1 — `ruff check --select X` lies about `RUF100`.** Isolating a rule disables all others, so every `noqa` naming a now-disabled rule reports as unused. `--select RUF100` reports **132** findings; the true count under the project's full `select = ["ALL"]` config is **4**. Always enumerate with the full config and `grep` for the rule, never with `--select`.

**Trap 2 — the `ISC004` autofix leaves ragged indentation.** It wraps continuation strings in parentheses but does not re-indent them. `ruff format` must run immediately afterward, in the same task, or the result is valid but ugly code.

- [ ] **Step 1: Write the verification script first**

Ruff's `ISC004` fix only adds parentheses. Python's parser discards redundant parentheses and folds implicit concatenation into a single `Constant`, so **an unchanged AST proves no collection gained or lost an element and no string content changed**. If the fix had instead resolved a genuinely missing comma, the AST would differ — which is exactly the pre-existing bug that must be surfaced rather than silently absorbed.

Write this to `/tmp/isc004_ast_check.py`:

```python
"""Prove the ISC004 fix is semantics-preserving by comparing ASTs against HEAD."""

import ast
import subprocess
import sys

FILES = [
    "scripts/generate_config_docs.py",
    "scripts/generate_dogma_mapping.py",
    "src/mcp_zen_of_languages/languages/go/rules.py",
    "src/mcp_zen_of_languages/reporting/prompts.py",
]

failed = []
for path in FILES:
    before = subprocess.run(
        ["git", "show", f"HEAD:{path}"],
        capture_output=True,
        text=True,
        check=True,
    ).stdout
    with open(path, encoding="utf-8") as fh:
        after = fh.read()
    if ast.dump(ast.parse(before)) != ast.dump(ast.parse(after)):
        failed.append(path)

if failed:
    print("AST CHANGED - not a pure reformat. Inspect by hand:")
    for path in failed:
        print(f"  {path}")
    sys.exit(1)

print(f"OK: all {len(FILES)} files are AST-identical to HEAD")
```


The eight `frameworks/*/rules.py:12` sites are the identical `_principle()` helper replicated per framework. For example, `src/mcp_zen_of_languages/frameworks/react/rules.py:12` becomes:

```python
def _principle(  # noqa: PLR0913, PLR0917
    rule_id: str,
    principle: str,
    category: PrincipleCategory,
    severity: int,
    description: str,
    patterns: list[str],
    recommendation: str,
) -> ZenPrinciple:
```

Apply mechanically across all 13 sites:

```bash
uv run ruff check --output-format=concise 2>/dev/null | grep PLR0917 | cut -d: -f1 | sort -u | \
  xargs -I{} python3 - {} <<'PY'
import re, sys
path = sys.argv[1]
with open(path, encoding="utf-8") as fh:
    src = fh.read()
src = re.sub(r"# noqa: PLR0913(?!, PLR0917)", "# noqa: PLR0913, PLR0917", src)
with open(path, "w", encoding="utf-8") as fh:
    fh.write(src)
print(f"updated {path}")
PY
```
